Pre-registered 2026-10-31 (Istanbul, UTC+3) before any repository of this batch was cloned or run. Tool state: commit 7fe9214 plus this file and the two scripts scripts/heldout.sh and scripts/heldout_summary.py.
Purpose: our patterns and prompts were tuned on the shop example and indsl, so those results are not an independent test. This batch runs the whole chain on code we have not tuned on, and reports every stage, including zeros.
Rule for the list: every repository of the three static counts in docs/CENSUS.md (docs/census/repos.json, repos2.json, repos3.json) that has at least one pattern site in a .py file (notebooks do not count), minus polyaxon/traceml (already worked, docs/REAL_PROJECT.md) and ryfeus/lambda-packs (it holds a vendored copy of pandas itself). Eight repositories remain:
  abu bbfamily/abu; modin modin-project/modin; pytimetk business-science/pytimetk; pygraphistry graphistry/pygraphistry; siuba machow/siuba; hamilton stitchfix/hamilton; pandera unionai-oss/pandera; django-rest-pandas wq/django-rest-pandas.
Procedure, the same for each repository (scripts/heldout.sh): shallow clone of the default branch (timeout 180 s, a failed clone is reported, not retried); `discover --limit 10` (parse only); `propose` with meta-models/muse-spark-open-1026, effort low, 4 inputs, 2 tries; `scan` with the same model, effort low, 3 attempts per function, the pinned pandas 2.3.3 and 3.0.6 environments of scripts/setup_envs.sh (so a function that needs other third-party libraries is reported as invalid, and we do not build project environments). One run per repository; no repeat of a run that looks bad or good.
Reported afterwards, one row per repository (scripts/heldout_summary.py): commit, candidates listed, sites skipped, targets that got inputs, classes (healthy, silent, loud, invalid), repaired or not, tokens. Zero rows stay in the table.
Not changed after seeing the results: the patterns, the prompts, the gates, the model, the effort and the list. A bug in our own tooling found during the run is fixed and reported as a bug fix, and the affected repository is run again once with the fix, with both runs shown.
What this can show: how often the chain finds a function it can run, and what happens to it, in eight projects chosen by a fixed rule. What it cannot show: a rate over all projects; `healthy` holds for the inputs used; the repositories were chosen because they had a pattern site, so they are more likely than average to have candidates.
