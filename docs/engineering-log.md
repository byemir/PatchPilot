- Added patchpilot/differential.py: generated-input differential. Oracle = ORIGINAL code on the OLD library; candidate = PATCHED code on the NEW and on the OLD library. Inputs come from a seeded, stdlib-only mutator over the seed probes (inputs.json + hidden_inputs.json): per-JSON-path value envelopes for numbers, digit-run mutation and token crossover for strings, drop/dup/shuffle/grow/truncate for lists. Reproducible (seed) and zero model tokens.
- Design: two tiers. "core" probes keep numbers inside the envelope seen in the seeds and any divergence fails; "wide" probes leave it and are only reported, because out-of-contract inputs can legitimately differ (np.asarray([-1], dtype=uint8) raises OverflowError on NumPy 2 and wraps on 1.x, nothing a patch should preserve). Probes where the oracle itself raised are skipped. Fewer than 20 valid probes gives verdict WEAK instead of a silent pass.

- Observed differences, each reproduced by running both versions: (1) Timestamp + pd.offsets.Day(1) across a DST spring-forward gives 13:00 on pandas 2.3.3 (24h Tick) and 12:00 on 3.0.6 (calendar day); Timedelta(pd.offsets.Day(2)) raises ValueError on 3.0.6 (loud, so not used). (2) Series.astype(str) turns None into 'None' and NaN into 'nan' on 2.3.3, but both stay NaN on 3.0.6 (default str dtype); value_counts then drops them. (3) DataFrame.value_counts(sort=False) returns sorted keys on 2.3.3 and first-appearance order on 3.0.6. Series.value_counts(sort=False) gave the same order on both for int, float, str, bool, datetime and categorical inputs, so it is NOT a case. (4) groupby on a categorical: observed defaults to True on 3.0.6 (empty categories vanish); groupby.apply no longer passes the grouping column (include_groups=True raises). (5) NumPy 2 NEP 50: float32 scalar * Python float stays float32 (was float64), so sums differ in the 7th digit and `x > bonus` flips at boundaries.
